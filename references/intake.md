# Intake and publication

Read `<downloads>` and explicit chat attachments. Use the scanner with explicit paths: `python3 <skill-dir>/scripts/vinted-intake.py --downloads <downloads> --state-dir <workspace>/work/vinted-intake scan`, then run `stage <selected paths>` with the same options. Consult `--help` when needed. If the baseline is missing, inventory current files and compare against the log and existing listings before creating it. Do not silently mark all current files as processed. Never move or delete originals. Ignore unrelated files only after review. Content hashes deduplicate intake; staged does not mean published.

Group photos by visual similarity, timestamps, and labels. Inspect images rather than inferring size or condition from filenames. Keep source paths/hashes, brand, item type, size, condition, price, and existing item ID or publication state for each group.

When a price is missing, ask in one batch for a price indication per item or permission to set it. An explicit price is sufficient pricing authority. With delegated pricing, compare current secondhand listings of similar brand, model, and condition; record the chosen asking price and source. Do not guess missing sizes or authenticity. Ask only what blocks publication and continue with complete items.

Check existing listings before publishing. Identify photo updates by image and item ID. Preserve old photos unless instructed otherwise. Photo order: clear human wearing photo/selfie when available, whole item, back, label, details, defects. Upload multiple photos individually through the supported browser upload tool when required. Check the final order before saving. Preserve original images if re-uploading is necessary.

Use a specific title and short factual description in the configured listing language, defaulting to English. Fill category, brand, label size, condition, and agreed price. Record unusual fit and visible measurements precisely. Verify all fields and images, publish within the pricing mandate, then confirm the item ID and visible state. “Pending” means submitted, not confirmed live. Log the ID and add the item to the dashboard. After a timeout, inspect the profile or inbox before retrying publication.
